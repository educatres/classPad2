# ClassPad2 即時同步手寫白板

線上使用：[ClassPad2](https://educatres.github.io/classPad2/)。原始碼：[educatres/classPad2](https://github.com/educatres/classPad2)。

我一直很喜歡使用 Google Jamboard 進行教學，因為它能讓學生在課堂中即時書寫、分享想法並彼此互動。可惜 Jamboard 服務結束後，我始終找不到完全符合需求的替代工具。市面上雖然已有不少功能完整的訂閱平台，但我通常只會在每學期的特定幾週密集使用，若為了短期的教學需求而長期訂閱，不太符合我的使用情境。

此外，我也不希望教學工具蒐集學生的個人資料，或要求學生另外註冊帳號。由於每次授課的班級與學生可能不同，若只是為了一堂課，就要求學生申請新的服務帳號，不僅增加學生的負擔，也會占用寶貴的上課時間。因此，我用 AI 協助開發了這套即時互動白板，並開放原始碼，供有需要的老師免費使用。

考量到並非每位老師都熟悉程式設定與系統部署，老師自行下載原始碼、建置環境及架設服務，仍有一定的使用門檻，因此本平台也提供可直接開啟使用的線上版本。由於伺服器資源有限，每次建立的課程白板可使用十小時，時間到期後，系統將自動清除課程資料；建立課程的次數則不受限制。老師可以在每節課開始前建立新的白板，課程結束後下載所有學生的白板資料，再自行刪除課程，或等待系統自動清除。

每位老師建立的課程皆為彼此獨立的空間，無法查看其他老師或其他課程的內容，在提供便利課堂互動的同時，也盡可能兼顧學生隱私與教學資料安全。

在開發過程中，我也依照自己的教學需求，加入了五項功能：

1. 「QR Code 快速進入」：本工具針對「生生用平板」的課堂情境設計。老師建立學生名單後，會為每位學生產生專屬 QR Code；學生只要使用平板掃描，即可進入自己的個人白板，無須註冊或登入。系統亦加入裝置綁定機制，可避免學生誤入或使用其他同學的白板空間，兼顧學生作品的獨立性。
2. 「全班即時監看與批注」：老師可以透過多格畫面，同時查看全班學生的即時手寫內容，不必逐一走到學生座位旁確認進度。當發現學生需要協助時，老師也能直接在該名學生的白板上遠端進行批注、圈選或提示，學生可立即看到老師的回饋，適合應用於課堂練習、分組活動及個別指導。
3. 「PDF 題目派送」：當老師希望進行解題、填空、標示或課堂小考時，可以開啟本機 PDF、框選題目截圖，先調整大小與位置，再派送至全班的新白板頁面。學生可直接在題目上書寫、作答或繪製標記，省去逐一發放紙本或請學生自行下載檔案的步驟。
4. 「學生作品即時投影」：課堂中經常需要讓全班觀摩某位學生的解題方式或優秀作品，因此平台提供指定學生畫面的投影功能。老師可以在監看畫面中選擇特定學生，將其白板即時顯示在教室投影機或電子白板上；學生的書寫內容與老師的批注也會同步更新。實際上課時，建議老師可另外準備一台平板作為控制與監看裝置，在觀察全班書寫狀況的同時，隨時選擇適合的學生作品進行全班討論與示範。
5. 「打包下載」：課程結束後，老師可以將全班學生的白板畫面一次打包下載為圖檔。

## 功能

- Firebase Anonymous Authentication 與 Realtime Database 即時同步
- 老師建立課堂、批次匯入最多 80 位學生、QR Code 與 CSV 連結
- 學生首次開啟連結後綁定匿名裝置，可由老師解除
- 學生只需開啟個人專屬網址即可綁定，不使用老師六位數密鑰
- 三層 Retina Canvas、Pointer Events、Apple Pencil 壓力、整筆橡皮擦
- 老師講解、放大批注與學生白板均使用約 62 px 單排圖示工具列，窄螢幕可左右滑動；保留完整中文操作提示及至少 44 px 點擊範圍
- 學生提供黑／藍／綠圓形畫筆按鈕，老師講解與放大批注另提供紅色；點選即切換顏色並回到畫筆，選中色顯示外框與勾選
- 學生手寫預設開啟筆畫平滑，可在工具列切換並記住此瀏覽器的設定
- 本機復原/重做、雙指 25%～400% 縮放與拖曳，學生與老師批注工具列提供每次 10% 的放大／縮小按鈕
- 老師講解與學生白板提供手指圖示的拖動工具，可用滑鼠、單指或觸控筆平移畫板；重設視圖可恢復 100% 並置中
- 4:3 固定白板比例，4／6／8／12 格即時監看與免翻頁的全班總覽、釘選優先排序、搜尋/篩選/輪播、全螢幕批注
- 老師獨立多頁講解白板，完成筆畫保存、復原／重做、整筆橡皮擦與同步狀態
- 永久老師連結與未遮蔽六位數密鑰，密鑰正確即可登入，不限老師連線數量
- 老師鎖定、清除圖層、本機合成下載 PNG
- 講解白板左側 PDF 面板，可隱藏、調整寬度、連續捲動所有頁面、框選並預覽派送
- 拒絕預設存取的 Firebase Security Rules 與 Emulator 權限測試

## 老師講解與全班總覽

在「課堂設定」或「學生畫面」按「講解白板」，即可使用獨立的多頁白板；沒有學生也能使用。請自行在會議軟體分享此視窗。畫筆、整筆橡皮擦、顏色、粗細、平滑、復原／重做與雙指縮放／拖曳均沿用既有 Canvas。新增講解頁與清除本頁不影響學生作答或個人批注。

講解、放大批注及學生白板工具列固定單排，優先使用圖示；粗細、便條顏色與頁數保留簡短文字。將滑鼠停在圖示上可看完整中文提示，平滑、鎖定、投影及目前工具會顯示選取狀態。顏色圓鈕保留 48 px，其餘按鈕至少 44 px；工具列空間不足時可左右滑動，鍵盤聚焦操作也會捲至可見位置。版面與操作驗證見 [BOARD_TOOLBAR_VALIDATION.md](./BOARD_TOOLBAR_VALIDATION.md)。

講解白板與學生白板在畫筆旁提供手指圖示的拖動工具。選取後，按住滑鼠左鍵、單指或觸控筆即可平移整張白板，100% 及縮放後都能使用；題目、筆跡、文字與便條貼會一起移動。切換工具保留視圖，翻頁則恢復 100% 與原點並保留工具；「重設視圖」可隨時還原。拖動不更改作答、復原歷史或 Firebase 內容，也不影響完整白板匯出。學生被鎖定時仍可拖動與縮放，無法書寫、擦除或復原／重做。PDF 側欄保持獨立捲動。操作與驗證範圍見 [BOARD_PAN_VALIDATION.md](./BOARD_PAN_VALIDATION.md)。

筆跡先在本機畫出，完成後才保存。請確認「已同步」再離開；「離線」或「同步失敗」表示仍可能有未保存內容，可保留視窗恢復連線或按「重試保存」。未確認寫入時會阻止翻頁，離開前會提示。重新整理只恢復資料庫已確認內容，不提供離線持久化。復原／重做歷史只保留本裝置本次開啟期間，切頁後仍保留，清除本頁會重設該頁歷史。清除影響共用的本頁資料，需先確認。

監看頁新增「全班總覽」，可垂直捲動查看最多 80 位學生；原有 4／6／8／12 格仍可選用。每人只載入最近書寫的一頁，含題目底圖、學生筆跡與文字、老師批注與便條貼。可釘選、放大批注，返回時保留模式與位置。篩選時顯示目前與全班人數，按「恢復全班」清除篩選；總覽不啟用分頁輪播。縮圖最寬 480 像素，減少 Canvas 記憶體，但仍需下載完整的目前頁筆畫，80 人及大量筆跡會增加流量；驗證數據與限制見 [LECTURE_BOARD_VALIDATION.md](./LECTURE_BOARD_VALIDATION.md)。

講解內容只保存在 `lectureBoards/{classId}`，與學生作答、個人批注、展示頁和 PDF 派送資料分開。只允許本課堂老師讀寫，不新增學生觀看權限、講解筆尖串流或後端；從原始課堂建立時間起算十小時，手動刪課與到期清除會一併移除。**部署前請先更新 Firebase Realtime Database 規則**，舊規則無法使用講解功能。

## PDF 題目派送

在「講解白板」工具列按「PDF 題目派送」文件圖示，即可展開左側面板；老師管理頁的同名按鈕會前往講解頁並展開面板。載入本機 PDF 後，預設使用「瀏覽」模式，依頁序上下滑動閱讀全部頁面，也可輸入頁碼跳轉、放大／縮小或符合面板寬度。

PDF 側欄使用單排工具列：「載入／更換」、頁碼與跳頁箭頭、縮放比例、「瀏覽」、「框選」、「整頁」。點縮放比例展開放大／縮小及「符合」，操作說明收在標題旁的 ⓘ；按 Escape 或點外側即可收起。按鈕保留至少 44 px 點擊範圍，窄面板可左右滑動工具列，增加 PDF 閱讀空間。

拖曳面板右側分隔線可調整寬度，也可聚焦分隔線後使用左右方向鍵、Home／End。隱藏後再開啟會保留本次 PDF、捲動位置、縮放、框選與未派送的預覽。在同一瀏覽器分頁切換課堂設定、學生畫面與講解白板，或重新整理後，會還原該課堂的 PDF、縮放及垂直／水平閱讀位置，並記住面板是否展開；更換成功後重設閱讀位置，無效檔案不會移除原 PDF。正常關閉分頁／視窗後，重新開啟需重新選檔。面板寬度另外保存為瀏覽器偏好。調整面板寬度或 PDF 縮放時保留閱讀位置與正規化選取範圍。窄螢幕及平板直向改用覆蓋式 PDF 面板，按「隱藏面板」即可返回白板；講解頁面與筆跡保持原狀。

切換「框選截圖」，在單一 PDF 頁面拖曳題目範圍，或按「截取目前整頁」。截圖從原始 PDF 產生，不擷取低解析側欄畫面。完成後進入 4:3 學生白板版面預覽：拖曳截圖調整位置、拉右下角等比例縮放，或用 10%～150% 比例滑桿微調，也可按「置中並符合白板」還原。白板外的部分不會顯示，派送時會將此大小與位置套用至全班新白板。確認後按「派送為新白板」；需要重選時按「返回 PDF 重新框選」。按「稍後派送」可先繼續閱讀，再從面板底部「檢視截圖與派送」返回同一預覽。一次框選不跨頁。

題目大小與位置在派送前的版面預覽中設定。監看及放大批注頁不再提供派送後的大小或位置調整，也不支援 Google Drive 底圖。

每次派送會在全班頁面末尾新增一頁，保留所有既有作答。學生會看到新題目提示，可自行按「開啟題目」，不會被強制切頁。晚加入或重新整理的學生仍可取得教材。監看、放大批注、被動展示、單張 PNG 與全班 ZIP 都會包含題目；只有題目、沒有任何筆記的頁面維持略過 ZIP 匯出。

PDF 原檔、檔名與本機路徑不會上傳，解析與裁切均在老師瀏覽器執行。**僅老師確認派送的 JPEG 截圖會存入 Realtime Database，保留到課堂清除。** 未派送截圖只留在視窗記憶體，關閉或重新整理即清除；不提供一般圖片或檔案上傳，不使用 Firebase Storage。截圖讀取採有上限的記憶體快取，不保存至 localStorage、IndexedDB 或 CacheStorage。

跨功能保留 PDF 使用老師裝置的 IndexedDB 加密暫存原檔；解密金鑰、閱讀位置與面板狀態僅放在 sessionStorage，按課堂與老師 UID 區分。正常關閉分頁後金鑰失效，新分頁無法還原；成功更換 PDF 會覆寫該份暫存。下次載入 PDF 時清理超過 24 小時的加密殘留，課堂權限及十小時期限仍照常檢查。若瀏覽器禁止本機暫存、空間不足或已清除資料，會以中文提示重新選檔，目前開啟的 PDF 仍可使用。跨頁還原不包含尚未派送的截圖與版面，離開前仍會提醒。

閱讀區保留所有頁面的位置，只依可見範圍繪製附近最多五頁，每頁預覽不超過 150 萬像素；更換檔案或離開時取消繪製並釋放資源。派送重試沿用同一操作 ID，尚未確認時鎖定截圖與版面。隱藏面板不會取消派送；有待處理截圖或未確認結果時，離開前會提示。這次介面整合沿用既有 Firebase 路徑與 Rules，不需資料遷移或額外規則部署。驗證範圍見 [PDF_LECTURE_PANEL_VALIDATION.md](./PDF_LECTURE_PANEL_VALIDATION.md)。

初版限制：PDF 最多 30 MiB、200 頁；截圖長邊最多 1600 像素、256 KiB；介面每課堂最多派送 20 張。加密 PDF 需先解除密碼。僅進行中且未到期的課堂可派送，離線時不開始；連線中斷後會等待寫入確認，重試沿用同一操作 ID。成功訊息表示資料庫已確認新增頁面，不表示每台學生裝置皆已收件。

截圖只保存於 `classMaterials/{classId}/{pageId}`，頁面使用 `rtdb-capture` 參照。`classMaterialSessions/{classId}/{uid}` 只定位已綁定學生白板；每次讀取仍由 Rules 驗證目前 UID、token、啟用狀態、期限與該頁參照。老師關閉本機 PDF 不影響已派送教材。沿用建立滿十小時失效政策，由下一次有權老師開啟前端時清除教材與 session；沒有伺服器背景排程。仍消耗 Spark 的資料庫儲存、下載與連線額度，並非無限免費。

新舊課程一律從原始 `createdAt` 起算十小時；既有三小時的 `expiresAt` 不再提前限制筆跡、教材或展示。老師使用首頁、管理頁或監看頁時，以同一筆原子更新同步 `classes/{classId}/expiresAt` 與 `publicClasses/{classId}`。所有寫入期限與學生／展示教材讀取期限均由 Rules 依課程建立時間檢查，不能透過修改 `expiresAt` 或重新開啟課程續期。老師授權邀請仍為十分鐘，且不能跨越課程期限取得權限；已被刪除的課程不會還原。更新後請重新整理已開啟的頁面，以套用新期限。

學生與展示端在閒置後遇到期限監聽錯誤時，會保留目前白板與最後有效期限並自動重試；回到前景或恢復網路也會立即重試。只有有效期限確實到達才顯示課程到期，監聽失敗或日期缺漏不會被當成到期。

本次功能需一併更新 `database.rules.json` 後才可在線上使用。PDF.js 與 worker 固定為同一版本；Vite 會打包同版的 CMap、標準字型、WASM 與 ICC 資產，遵守 GitHub Pages 子路徑，學生入口不載入 PDF.js。請勿只部署前端而保留舊規則。

## 本機開發

需求：Node.js 22、pnpm 11、Java 21（只在執行 Firebase Emulator 時需要）。

```bash
cp .env.example .env
pnpm install
pnpm dev
```

在 `.env` 填入 Firebase Web App 設定。只有明確啟動 Emulator 時，才把 `VITE_USE_FIREBASE_EMULATORS` 設為 `true`。

## 驗證

```bash
pnpm test
pnpm test:rules
pnpm build
```

`test:rules` 會啟動 Authentication 與 Realtime Database Emulator，驗證老師、學生、其他匿名使用者和未登入使用者的允許/拒絕案例。
可使用 `npm run test:rules -- --project demo-classpad` 在示範專案中驗證規則；Windows PowerShell 若停用 npm.ps1，可使用 `npm.cmd test`、`npm.cmd run build` 與 `npm.cmd run test:rules -- --project demo-classpad`。

## Firebase 設定

1. Authentication → Sign-in method：啟用 Anonymous。
2. 建立 Realtime Database，區域建議 `asia-southeast1`，不要使用公開測試規則。
3. 安裝並登入 Firebase CLI，再部署規則：

   ```bash
   pnpm exec firebase login
   pnpm exec firebase use classpad2
   pnpm exec firebase deploy --only database
   ```

4. Authentication → Settings → Authorized domains 加入：
   - `educatres.github.io`
   - `localhost`
   - `127.0.0.1`

5. 權限資料會在首次使用後依規則建立於 `classes`、`students`、`boards`、`activeStrokes`、`presence`、`userClasses`、`teacherKeys`、`teacherKeyClaims` 與 `boardLookup` 節點，不需手動建立空資料表。課程建立滿 10 小時後，會在老師下次使用首頁、管理頁或監看頁時自動清除。

## GitHub Pages

Repository → Settings → Pages 的 Source 設為 **GitHub Actions**。GitHub Actions 建置使用 `/classPad2/` 路徑，本機開發使用 `/`。

推送 `main` 後，`.github/workflows/deploy-pages.yml` 會測試、建置並部署 `dist`。Repository 的 Actions Secrets 需要：

- `VITE_FIREBASE_API_KEY`
- `VITE_FIREBASE_AUTH_DOMAIN`
- `VITE_FIREBASE_DATABASE_URL`
- `VITE_FIREBASE_PROJECT_ID`
- `VITE_FIREBASE_APP_ID`

Firebase Web API key 會包含在公開前端 bundle；資料授權完全由 Authentication 與 `database.rules.json` 強制執行。禁止提交 Service Account、Admin SDK 私鑰或 `.env`。

## 權限與隱私

Firebase 匿名驗證明確使用瀏覽器本機持久化，建立課堂後也會暫存該課堂與老師 UID，跳轉管理頁時會先恢復同一身分再讀取權限。每個課堂另有永久老師連結與未遮蔽的六位數字密鑰；新瀏覽器輸入正確密鑰後會加入課堂管理員，並與其他老師享有相同完整權限，不限連線數量。請妥善保管老師連結與密鑰，只應輸入學生座號或暱稱，不應輸入身分證字號、電話、Email、住址或醫療資料。

完整需求請見 [SPEC.md](./SPEC.md) 與 [即時同步手寫白板規格書.md](./即時同步手寫白板規格書.md)。
